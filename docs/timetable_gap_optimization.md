# Gaps in timetables

One of the available constraints allows the number of "free" lessons in a timetable to be limited. This may be a difficult constraint to check during the construction of a timetable. Although an algorithm which considers gaps when it is placing lessons is conceivable, it might make other optimizations difficult to implement. Checking the gap constraint later – when a timetable has been fully constructed, or reached another stage where the fulfilment of the gaps constraint cannot be achieved – is unlikely to be particularly efficient, invalid paths may have been followed for quite a time.

The number of gaps which can arise is strongly related to other constraints, especially those determining the available time slots. It might be worth experimenting with the number of blocked time slots as a way to reduce the number of gaps, as blocking slots tends to increase efficiency. The decision as to which additional blocked lessons to try would not be easy. It depends on various other constraints (e.g. min/max lessons per day, lunch breaks, end times, number of afternoons). Also, as the runs are potentially quite lengthy, only a limited number of trials may be possible. In general, gap reduction should probably be left to the later stages of timetable optimization, once other sticking points have been ironed out.
